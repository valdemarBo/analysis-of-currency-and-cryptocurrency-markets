# Анализ валютных и криптовалютных рынков

**Комплексный ETL-пайплайн и аналитический дашборд для мониторинга фиатных валют и криптовалют.**

Проект охватывает полный цикл инженерии данных: автоматизацию сбора данных через Apache Airflow (Docker), хранение и трансформацию в PostgreSQL (Raw Data → Materialized Views), визуализацию в Power BI и настройку мониторинга через Telegram Bot.

**Инструменты:** Python, Apache Airflow, PostgreSQL, Power BI, Docker, Git.

---

## Введение

Данный проект представляет собой комплексный аналитический пайплайн, моделирующий работу реального Data Product в финансовом секторе. Он собирает данные о курсах 29 мировых валют к Евро (API Frankfurter) и ценах на ведущие криптовалюты (API CoinGecko).

Архитектура проекта построена по стандарту **ELT** (Extract, Load, Transform): сначала данные в неизменном виде загружаются в «сырой» слой (Raw Layer), а затем с помощью оконных функций SQL и материализованных представлений (Data Marts) преобразуются в готовые витрины для BI-систем. Проект демонстрирует навыки написания отказоустойчивых ETL-скриптов, оркестрации процессов, моделирования данных (схема «Звезда») и продвинутой аналитики.

---

## Цели исследования

### 1. Автоматизация сбора данных (Data Engineering)
Настройка DAG-ов в Apache Airflow для запуска Python-скриптов по расписанию (cron), обеспечение идемпотентности вставки данных (`ON CONFLICT DO UPDATE`) и обработка сетевых ошибок (ретраи, таймауты).

### 2. Моделирование данных и оптимизация (DBA)
Проектирование реляционной структуры в PostgreSQL. Создание материализованных представлений (Materialized Views) для тяжелых расчетов (проценты изменений, волатильность) и построение индексов для мгновенного отклика BI-инструментов.

### 3. Финансовая аналитика и визуализация (BI)
Построение интерактивного дашборда в Power BI с использованием схемы «Звезда» (Date Dimension). Создание сложных мер на языке DAX для расчета волатильности, изменений за неделю (WoW) и статистических экстремумов.

### 4. Мониторинг и Observability (DevOps)
Настройка бота в Telegram, который автоматически уведомляет о статусе выполнения ETL-пайплайна, указывая конкретный шаг, на котором произошла ошибка.

### Процесс загрузки данных

**1. Извлечение (Extract)**  
DAG-и в Airflow (`fx_etl_daily` и `crypto_etl_daily`) запускаются по будням. Python-скрипты обращаются к публичным API с использованием библиотеки `requests`.

**2. Загрузка (Load)**  
Данные записываются в базу PostgreSQL. Для защиты от дубликатов при повторных запусках используется конструкция `INSERT ... ON CONFLICT DO UPDATE`.

**3. Трансформация (Transform)**  
В базе данных настроены Materialized Views (`dm_fx_daily`, `dm_crypto_daily`). После каждой загрузки Airflow отправляет команду `REFRESH MATERIALIZED VIEW`, которая пересчитывает оконные функции (LAG) и обновляет витрины.

### Исследовательский анализ данных (EDA) и инженерия

#### Проверка качества данных и идемпотентность
При проектировании первичных ключей (Primary Keys) в таблицах `fx_rates` и `crypto_rates` была обеспечена защита от дублирования.

```sql
-- Пример создания таблицы с защитой от дубликатов
CREATE TABLE IF NOT EXISTS crypto_rates (
    rate_date   DATE NOT NULL,
    coin_id     VARCHAR(20) NOT NULL,
    price_usd   NUMERIC(18, 2) NOT NULL,
    loaded_at   TIMESTAMP DEFAULT NOW(),
    PRIMARY KEY (rate_date, coin_id)
);
```
